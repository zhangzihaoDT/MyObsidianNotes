# 我用 AI 做了一个家务积分机器人，让隐形家务被看见

你用AI做什么？用AI赚到钱了吗？

我把AI用于改造自己的生活，比如让打工人在节假日也能不当冤大头的出去玩一下，比如让隐形的家务劳动显性化。

今天就和大家分享一下我的家庭 AI 小助手：小哈皮的开发实践，你可以直接复制全文给 AI，你帮你顺一条更完整的step-by-step指南。我把思路写出来。

## 1. 向 AI 阐明需求

一开始，我向 AI 描述了一个很简单的需求：

“我想做一个家务积分小程序。这个小程序有两个用户，功能很简单：语音输入，系统判断任务类型，计分落表，形成看板。”

这个需求看起来很简单，但一旦开始拆解，会被拆得非常具体。

它至少包含五个模块：

1. 输入入口
   例如：微信小程序、飞书多维表格表单、Notion 表单。

2. 数据表 / 数据库
   例如：飞书多维表格、Supabase。

3. AI 识别
   需要对输入内容进行理解，判断任务类型。
   例如：OpenAI、DeepSeek、豆包。

4. 语音识别
   例如：微信同声传译插件、腾讯云 ASR、火山 ASR。

5. 看板
   例如：飞书仪表盘、小程序页面。

## 2. 第一个方案：微信小程序

我第一个想到的方式，是把这个小程序放在微信里，用微信小程序实现。

但一算价格，有点绷不住。

两个人自用版本，大致成本如下：

| 成本类型                           | 预估费用                             |
| ---------------------------------- | ------------------------------------ |
| 小程序认证 / 备案 / 域名等固定成本 | 约 300–500 元 / 年                   |
| 服务器                             | 约 459–510 元 / 年，或者用活动价更低 |
| 语音识别                           | 约 90 元 / 年以内                    |
| LLM 任务识别                       | 基本可以忽略，通常每月几分钱到几毛钱 |
| 数据库                             | 免费或包含在服务器里                 |
| 合计                               | 约 900–1,200 元 / 年                 |
| 折算月成本                         | 约 75–100 元 / 月                    |

如果用云厂商活动价，数据库直接放服务器里，甚至可以压到：

500–800 元 / 年左右。

但对于一个两个人自用的家务积分小工具来说，这个成本还是偏高。

## 3. 第二个方案：飞书生态

第二种方案，是用飞书现有生态完成。

对比一下复杂度：

| 模块     | 微信小程序自建             | 飞书生态                        |
| -------- | -------------------------- | ------------------------------- |
| 用户登录 | 要自己接微信登录           | 飞书账号天然解决                |
| 双人权限 | 要自己设计家庭绑定         | 直接共享多维表格 / 群组         |
| 数据库   | 自建 SQLite / Postgres     | 多维表格就是数据库              |
| 看板     | 自己开发图表页             | 多维表格仪表盘直接做            |
| 自动化   | 自己写后端逻辑             | 多维表格自动化 / 工作流         |
| 语音入口 | 小程序录音 + ASR           | 飞书消息 / 表单 / 机器人入口    |
| AI 识别  | 后端调用 LLM               | 仍需调用 LLM，但流程更轻        |
| 部署     | 需要后端服务               | 可以极少后端，甚至半自动        |
| 成本     | 服务器 / 域名 / 小程序认证 | 主要是飞书版本 / LLM / API 成本 |

总结下来，五大要素里，飞书生态基本都有现成的：

1. 入口：飞书群
2. 数据表：多维表格
3. ASR 服务：飞书本身好像就可以语音转文字
4. 【待补充】
5. 看板：多维表格仪表盘直接做

剩下来的，就是一个 LLM 服务。

毫无疑问，不带犹豫，直接上我们国民级宝藏：DeepSeek Flash，约等于没成本。

所以我果断选择了这个方案。

接下来，开始实现这个“小程序”。

## 4. 第一步：AI 实现功能

在真正写代码之前，需要先准备飞书侧的基础配置。

### 4.1 创建企业自建应用

在飞书开放平台创建一个企业自建应用，不要用“自定义机器人”。

### 4.2 开启机器人能力

进入应用后台后，找到类似：

应用能力 / 添加能力 / 机器人

开启机器人能力。

这一步之后，你的应用才会以机器人形式出现在飞书里。

然后回到飞书群里，把机器人加进来。

### 4.3 记录基础配置

后面需要把这些配置填到 `.env`：

```env
FEISHU_APP_ID=
FEISHU_APP_SECRET=
FEISHU_VERIFICATION_TOKEN=
FEISHU_ENCRYPT_KEY=
```

### 4.4 配置事件订阅

事件订阅选择长连接方式就行，可以进行调试。

然后，把开发工作交给 AI：

机器人接收消息、解析消息、处理错误、调试接口，都是 AI 的工作。

有什么错，就复制错误信息，问 AI，让 AI 解决。

多一点耐心，几个循环之后，主链路就可以跑通。

## 5. 第二步：准备多维表格

前面的步骤，是为了让机器人可以获得你在群里 @ 它的消息。

接下来要做的是，让它把信息记录到多维表格中。

还是老规矩：

机器人接收消息、处理消息、记录消息、转化格式，都是 AI 的工作。

我们要做的，还是提前准备好基础设施：

1. 创建多维表格
2. 记录多维表格 Base 的 app_token
3. 记录表的 table_id
4. 把字段头部填好

需要准备的配置包括：

```env
FEISHU_BITABLE_APP_TOKEN=多维表格 Base 的 app_token
FEISHU_TABLE_RAW_INPUTS=raw_inputs 这张表的 table_id
FEISHU_TABLE_CHORE_RECORDS=chore_records 这张表的 table_id
```

然后，继续交给 AI。

老样子，有错误，或者哪里没整好，就继续问 AI。

这个阶段，就可以获得项目的 MVP 主链路。

例如，在飞书群里输入：

```text
@小哈皮 家务：我刚刚洗了碗，还拖了地
```

系统会完成：

```text
飞书群 @小哈皮 家务：我刚刚洗了碗，还拖了地
→ 长连接收到消息
→ 清洗 @机器人前缀
→ LLM 解析出 2 个任务
→ 本地积分规则计算 2 分
→ raw_inputs 写入 1 条
→ chore_records 写入 2 条
→ 机器人回复积分结果
```

之后可以继续打一些补丁。

比如我就遇到了时间格式不准确的问题，记录时间会变成：

```text
1970-01-01 00:00:00
```

这个问题也需要交给 AI 继续处理。

## 6. 第三步：真实部署

至此，我已经获得了一个完整的 MVP 项目。

但很快会发现一个问题：

如果使用长连接方式，本地 Mac 一旦息屏，就会断掉，机器人也就接收不到消息了。

因为家务机器人这种场景，需要 7×24 小时在线。

所以本地 Mac 方案天然不稳定。

我选择的部署产品是 Sealos。

Sealos 支持两种方式部署小程序：

1. 从 GitHub 仓库构建
2. 上传 / 使用 Docker 镜像

我选择了后者。

老样子，我们先做好准备工作。

### 6.1 在 Sealos 上创建应用

我选了最小单位：

```text
0.1 个 CPU 核心
256MB 内存
总计费用：0.09 元/天
```

### 6.2 把本地 Docker 镜像推到 Docker Hub

因为 Sealos 云端拉不到你本地电脑上的镜像，所以需要把镜像推到一个远程镜像仓库。

整个链路是：

```text
本地镜像 → push 到 Docker Hub / GHCR → Sealos 从远程镜像仓库 pull
```

### 6.3 注册 / 登录 Docker Hub

【待补充：这里可以补一两句 Docker Hub 的具体操作。】

### 6.4 在 Sealos 中填写镜像地址

镜像地址类似：

```text
docker.io/byte1717712/housework-feishu-bot:v0.1
```

然后启动。

至此，小哈皮就可以在 Sealos 上 7×24 小时服务了。

## 7. 最后的感受：超级简单的需求，也能被超低价格服务到

做完这个项目之后，我最大的感受不是“我做了一个多厉害的 AI 应用”。

恰恰相反，它的需求非常简单：

一个飞书群里 @ 机器人，说一句家务；
AI 判断是什么任务；
系统记分；
数据落到多维表格；
最后形成一个看板。

但就是这么简单的需求，背后其实有一整套基础设施在托底。

这个过程中，一众顶级供应商都在为你保驾护航：

- DeepSeek 提供模型服务
- 飞书提供群聊、机器人、多维表格和看板
- Docker Hub 提供镜像仓库
- Sealos 提供云端部署
- 火山引擎 / 其他云服务提供更多可选能力

最后算下来，这个小工具的运行成本非常低。

### 成本清单

| 项目       | 用途                         | 成本            |
| ---------- | ---------------------------- | --------------- |
| 飞书生态   | 群聊、机器人、多维表格、看板 | 免费            |
| DeepSeek   | LLM 家务任务识别             | 几乎可以忽略    |
| Docker Hub | 镜像仓库                     | 免费            |
| Sealos     | 云端 7×24 小时部署           | 约 0.09 元 / 天 |
| 合计       | 小哈皮常驻运行               | 约 2.7 元 / 月  |

这就是我理解的“大国基建”。

不是说一定要做多复杂、多宏大的东西，而是一个普通人有一个超级具体、超级生活化的小需求时，已经可以用非常低的成本，把它搭出来、跑起来，并且让它持续服务自己的生活。

对我来说，这就是 AI 最有意思的地方。
