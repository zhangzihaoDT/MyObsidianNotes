# 从今天起，进入随地大小班模式

今天做了个事，也是把我之前一直想实现的事做了

就是在手机或 pad 上控制电脑，让 Agent 干活，我随时随地拿结果。

比如「更新数据」「查看 XX 一些业务数据」

原来这些事都是在公司完成的，我一般也倾向于在工作时间完成工作相关事务。

但，这不是要放假了吗？万一要临时看个啥，总得有个人盯着吧

这个人最好就是我的电脑。

---

## 为什么值得自己搭一套，而不是直接用大厂产品

其实说到这里，你可能意识到了，这就是 workbuddy 的一些功能，比如手机端工作。

但，为什么值得自己做一个自己的 assitant 而不是直接用大厂的产品呢？

我的思考是：「用大厂办公 Agent，像住大酒店；自己搭一套，像收拾自己的家。」

这完全不是一个逻辑，现在「五星级大酒店」的办公能力已经白菜价给到每个打工人了？

但，「岗位，不是职业」

就好像随时可以召唤酒店工作人员为你提供服务，不如自己在家里找到一颗西瓜🍉，然后顺手从厨房拿出一把餐刀，切开它，直接用勺子🥄，蒯着吃，这等舒服，不是那种...

## 我是怎么做的

回到正题，我是怎么做的？小小记录一下，也分享给你：

我已经有了 service 这个能力层，这是我的日常工作文件夹，里面有常用的脚本，也经过积累，集结了 OCR 识别、notify 信息推送、websearch API、高德地图 API、常用的工作思路、我自己喜欢的视觉风格定义...

而这一切资产，都可以让我的 opencode 去执行。

现在要做的，就是，在这一层上再加一个 hub 层，作为独立控制。

实际上形成的是：

```
手机 / Web │ hub（命令入口） │ ▼ 本地执行 Agent │ ▼ service（真实业务能力）
```

（图）

自此，Mac 不再是一台电脑，而是一台 Worker

云端的 hub 非常轻。

目前配置只有：

0.2 CPU 512 MB RAM

实际测试下来，内存占用只有几个百分点。

因为真正重的东西都不在云端。

数据不在云端。

业务代码不在云端。

OpenCode 不在云端。

本地文件系统也不在云端。

既解决了「安全🔐、隐私」这些问题，又可以「省钱」，每天 0.2 元，٩(•̤̀ᵕ•̤́๑)ᵒᵏᵎᵎᵎᵎ

且这样的分离有一个巨大的好处：我的 service 作为核心能力可以持续迭代，而 hub 不需要，因为它就是个收集需求、拿执行结果的小应用。

## 对 Agent 工程的一个新理解

今天跑通之后，我对 Agent 工程有了一个新的理解

模型负责「想」。

Capability 负责「做」。

Runtime 负责：别死。

State 负责：知道现在做到哪。

Observability 负责：出问题以后知道为什么。

Worker 负责：真的把事情执行出来。

而 UI 只是最后那个最浅的入口。

所以我现在会怎么定义 hub？它不是：「一个 OpenCode 的 WebUI。」

而更接近：一个远程 AI Command Hub。用户只需要面对一个输入框。后面的能力可以持续扩张。
