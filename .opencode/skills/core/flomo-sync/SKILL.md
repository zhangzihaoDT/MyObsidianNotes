# Flomo Sync

## 适用场景

当用户表达以下意图时使用本 Skill：

- “同步到 Flomo”
- “记到 Flomo”
- “保存到 Flomo”
- “把下面这段整理成一条 Flomo”
- 直接粘贴一段原始想法，并要求沉淀为笔记

用户可以提供：

- 零散想法
- 一段较长的思考
- 会议或阅读摘录
- 分析结论
- 待办与决策
- 已经写好的 Markdown

## 目标

把用户粘贴的原始内容处理为：

1. 含义不变
2. 结构清晰
3. 适合在手机端快速阅读
4. 方便通过标签检索
5. 不带多余解释，可直接写入 Flomo

## 默认处理原则

### 1. 保留原意

- 不虚构事实、数字、来源或结论
- 不把推测改写成确定事实
- 不删除关键限定条件
- 用户原文已经清楚时，只做轻量整理

### 2. 轻结构化，不做报告化改写

Flomo 笔记应短、轻、可回看。默认不要使用复杂的多级标题、表格或长篇总结。

推荐格式：

```markdown
**一句话标题**

一句话核心判断或背景。

- 关键观察 1
- 关键观察 2
- 推论、问题或下一步

#主题标签 #内容类型
```

只在内容确实需要时使用小标题，例如：

```markdown
**标题**

**观察**

- ...

**判断**

- ...

**待验证**

- ...

#标签
```

不要为了套模板而强行生成“观察 / 判断 / 行动”。

### 3. 标题

- 自动生成一个 8～24 字的标题
- 标题应表达核心判断，而不是只复述主题
- 使用加粗标题，不使用一级标题
- 用户已经提供明确标题时，优先保留

### 4. 正文

- 优先保留用户有辨识度的原话
- 清理重复表达、口头停顿和无意义连接词
- 长句可拆分，但不要改变逻辑关系
- 并列信息使用项目符号
- 连续叙述保留为自然段，不必全部列表化
- 原文中的链接、引用、代码块和 Markdown 应保留

### 5. 标签

默认添加 1～3 个稳定、可复用的标签：

- 一个主题标签，例如 `#数据分析`
- 一个内容类型标签，例如 `#思考`、`#方法`、`#决策`、`#复盘`
- 必要时添加一个项目标签，例如 `#AKSignal`

标签规则：

- 优先复用用户原文已有标签
- 不生成过细、只会使用一次的标签
- 标签中不要包含空格
- 不添加与内容无关的标签

### 6. 长度

- 最终内容尽量控制在 1200 字以内
- 2000 字以内可直接同步
- 超过 2000 字时：
  1. 优先压缩重复和铺垫
  2. 保留结论、依据、限制和下一步
  3. 仍超过限制时，拆分为多条独立笔记
- 未经用户明确要求，不要静默丢弃关键内容

## 笔记类型识别

根据原始内容选择最自然的结构。

### 思考 / 洞察

```markdown
**核心判断**

核心观点。

- 观察：
- 推论：
- 仍需验证：

#思考 #主题
```

### 方法 / 框架

```markdown
**方法名称**

适用问题或目的。

- 输入：
- 方法：
- 输出：
- 注意事项：

#方法 #主题
```

### 决策 / 结论

```markdown
**决策主题**

决定：……

依据：

- ...
- ...

下一步：……

#决策 #项目
```

### 摘录 / 阅读笔记

```markdown
**摘录主题**

> 原始摘录

我的理解：……

来源：链接或书名

#阅读 #主题
```

仅在用户提供来源时写“来源”，不得自行补造。

### 待办 / 行动

```markdown
**行动主题**

- [ ] 下一步事项
- [ ] 验证事项

背景：……

#行动 #项目
```

## 执行流程

1. 获取用户粘贴的原始内容。
2. 判断它更适合“轻量整理”还是“结构化笔记”。
3. 生成最终 Markdown。
4. 检查：
   - 是否改变原意
   - 是否存在虚构内容
   - 是否有重复表达
   - 是否超过 2000 字
   - 标签是否稳定、相关
5. 调用与本 `SKILL.md` 同目录的 `flomo_sync.py`。
6. 优先通过 stdin 传入内容，避免 shell 引号和换行问题。
7. 根据脚本退出码返回同步结果。

## 推荐调用方式

在 Skill 目录中执行：

```bash
python3 flomo_sync.py <<'FLOMO_NOTE'
**标题**

正文内容。

- 要点 1
- 要点 2

#思考 #主题
FLOMO_NOTE
```

也可以显式传入标题和标签：

```bash
python3 flomo_sync.py \
  --title "标题" \
  --tags "思考,数据分析" <<'FLOMO_NOTE'
正文内容。
FLOMO_NOTE
```

发送前预览：

```bash
python3 flomo_sync.py --dry-run <<'FLOMO_NOTE'
要预览的内容
FLOMO_NOTE
```

## 返回规则

同步成功时，简洁返回：

```text
已同步到 Flomo。
```

同步失败时，返回脚本输出的可操作错误信息，例如：

- 未找到 `.env`
- 未配置 `flomo_api`
- 内容超过限制
- HTTP 请求失败
- 网络连接失败

不要输出 webhook URL，也不要在对话中展示 `.env` 内容。

## 约束

- 不修改用户本地笔记原文
- 不读取或输出与本次同步无关的文件
- 不显示、记录或回传 webhook
- 不在用户没有表达同步意图时自动发送
- 用户要求“只整理、不发送”时，只生成笔记，不调用脚本
- 用户要求“原样同步”时，不改写正文，只做必要的长度检查
