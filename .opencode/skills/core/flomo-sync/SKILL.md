# Flomo Sync

## 核心目标

用户在 OpenCode 对话框中直接粘贴想法、笔记、表格、摘录或分析内容后：

1. 保留用户原意和表达重点
2. 整理为适合 Flomo 阅读和检索的 Markdown
3. 通过 `flomo_sync.py` 同步到 Flomo
4. 返回简洁的同步结果

本 Skill 的主要职责是：

**整理格式，而不是替用户重新创作内容。**

---

## 触发方式

当用户表达以下意图时使用：

- 同步到 Flomo
- 记到 Flomo
- 保存到 Flomo
- 整理后同步到 Flomo
- 把下面这段做成 Flomo 笔记
- 原样同步到 Flomo

用户也可能直接粘贴一段内容，并通过上下文表明需要同步。

---

## 默认工作模式：保守整理

除非用户明确要求总结、改写或提炼，否则默认采用“保守整理”。

保守整理包括：

- 修正明显错别字
- 清理多余空行
- 统一中英文标点
- 优化 Markdown 间距
- 保留原有标题
- 保留原有段落顺序
- 保留表格、列表、引用、链接和代码块
- 保留用户已有标签
- 必要时对过长句子做轻微拆分

保守整理不包括：

- 不新增用户没有表达的观点
- 不改变结论强度
- 不将推测改成事实
- 不补充外部知识
- 不自行扩展案例
- 不把表格改写成项目列表
- 不为了套模板而增加“观察、判断、行动”等栏目
- 不删除用户有辨识度的原话

---

## 内容处理优先级

按以下顺序处理：

### 第一优先级：保留原始结构

如果用户内容已经具备以下任一结构，应优先保留：

- Markdown 表格
- 项目符号
- 编号列表
- 标题与正文
- 定义与总结
- 引用与评论
- 代码块
- 标签

例如，用户提供了表格，就继续使用表格，不要自动拆成列表。

### 第二优先级：改善可读性

只做必要的格式优化，例如：

- 为标题加粗
- 调整段落间距
- 统一术语
- 修正明显重复
- 原始内容直接传递给脚本，由 `normalize_input_content()` 统一处理换行和字面量 `\n`
- 将连续文本恢复为 Markdown 结构

### 第三优先级：二维内容转换

当检测到连续两行及以上包含 `|` 的内容时，必须执行以下转换：

1. 第一行视为字段名称
2. 后续行视为数据记录
3. 简单映射转换为箭头列表
4. 不在列表项目之间增加空行

例如：

```text
大类资产 | 风险暴露 | 交易工具 | 底层资产
股票 | A股乘用车 | 个股、汽车ETF | 上市公司股权
```

必须转换为：

```markdown
映射顺序：**大类资产 → 风险暴露 → 交易工具 → 底层资产**

- **股票** → A股乘用车 → 个股、汽车 ETF → 上市公司股权
```

概念定义：

```text
大类资产：决定收益来自哪一种经济资产。
风险暴露：决定具体承担哪一种价格或因子变化。
```

必须转换为：

```markdown
- **大类资产**：决定收益来自哪一种经济资产。
- **风险暴露**：决定具体承担哪一种价格或因子变化。
```

### 第四优先级：适度压缩

仅当内容存在明显重复时压缩。

压缩时应保留：

- 核心观点
- 定义
- 论据
- 限定条件
- 示例
- 最终结论
- 原有标签

---

## 标题规则

### 用户已有标题

优先保留用户标题，只做必要的标点或格式调整。

推荐格式：

```markdown
**不同资产的完整映射**
```

### 用户没有标题

只有在缺少标题且标题能明显改善检索时，才自动生成标题。

标题要求：

- 8～24 个字
- 描述内容本身
- 不夸大结论
- 不使用营销化表达
- 不引入正文中不存在的新判断

---

## 表格规则

Flomo 不适合展示 Markdown 表格（移动端阅读体验差）。竖线分隔的二维内容必须转换为箭头列表。

用户提供：

```text
大类资产 | 风险暴露 | 交易工具 | 底层资产
股票 | A股乘用车 | 个股、汽车ETF | 上市公司股权
```

必须转换为：

```markdown
映射顺序：**大类资产 → 风险暴露 → 交易工具 → 底层资产**

- **股票** → A股乘用车 → 个股、汽车 ETF → 上市公司股权
```

概念定义形式的冒号分隔行：

```text
大类资产：决定收益来自哪一种经济资产。
```

必须转换为：

```markdown
- **大类资产**：决定收益来自哪一种经济资产。
```

---

## 标签规则

### 优先保留用户标签

如果原文已有：

```markdown
#资产映射 #交易
```

默认原样保留。

### 自动补充标签

只有用户未提供标签时，才可以补充 1～3 个标签。

标签要求：

- 与内容直接相关
- 稳定、可重复使用
- 不使用过细的一次性标签
- 不加入正文未涉及的主题

不要将用户的标签擅自替换成另一套标签。

例如：

```markdown
#资产映射 #交易
```

不要自动改成：

```markdown
#资产映射 #交易框架 #投资方法
```

除非用户要求优化标签体系。

---

## 不同指令的处理方式

### “同步到 Flomo”

轻度整理后直接同步。

### “原样同步到 Flomo”

不改写内容，只进行换行恢复、编码清理和长度检查。调用脚本时传 `--raw`：

```bash
python3 flomo_sync.py --raw <<'FLOMO_NOTE'
原样内容
FLOMO_NOTE
```

### “整理后同步到 Flomo”

允许改善：

- 标题
- Markdown 格式
- 表格格式
- 段落和列表结构

但不得新增观点。

### “总结后同步到 Flomo”

可以压缩内容，但必须：

- 保留核心结论
- 保留关键依据
- 保留重要限定
- 不补充外部内容

### “改写成一条 Flomo 笔记”

可以进行更明显的语言整理，但仍应保持原意。

### “只整理，不发送”

只输出整理后的 Markdown，不调用同步脚本。

---

## 长度规则

Flomo 单条内容上限按 2000 字处理。

### 2000 字以内

直接同步。

### 超过 2000 字

按以下顺序处理：

1. 删除明显重复
2. 压缩铺垫
3. 保留结论、依据、限制和行动
4. 如仍超过限制，拆分成多条笔记

不得静默截断关键内容。

拆分时，每条笔记都应具备独立意义，并保留必要上下文。

---

## 强制执行流程

本 Skill 必须区分两个变量：

- `original_content`：用户直接粘贴的原始内容
- `final_note`：经过 Flomo 格式转换后的最终笔记

执行顺序：

1. 读取用户内容，保存为 `original_content`
2. 将字面量 `\n` 恢复为真实换行
3. 根据 Flomo 格式规则生成 `final_note`
4. 对 `final_note` 执行格式验收
5. 只有验收通过的 `final_note` 才能传给 `flomo_sync.py`
6. 除非用户明确要求"原样同步"，否则禁止将 `original_content` 直接传给脚本

调用示例：

```bash
python3 flomo_sync.py <<'FLOMO_NOTE'
这里必须是已经整理完成的 final_note，
不能是用户直接粘贴的 original_content。
FLOMO_NOTE
```

---

## Flomo 格式验收

调用同步脚本前，`final_note` 必须满足：

- [ ] 第一行是加粗标题
- [ ] 不包含作为段落分隔符使用的字面量 `\n`
- [ ] 不包含 Markdown 表格
- [ ] 非代码内容中不应保留竖线分隔结构
- [ ] 连续列表项之间不插入空行
- [ ] 不同内容区块之间保留一个空行
- [ ] 概念定义转换为项目符号：`- **术语**：解释`
- [ ] 用户原有标签保留在文末
- [ ] 不新增用户没有表达的观点
- [ ] 内容不超过 2000 字

如果 `final_note` 中仍存在类似内容：

```text
字段一 | 字段二 | 字段三
值一 | 值二 | 值三
```

说明格式转换尚未完成，**禁止调用同步脚本**。

---

## 同步前检查清单

同步前必须确认：

- [ ] 原意没有改变
- [ ] 没有新增事实或结论
- [ ] 推测没有被改成确定判断
- [ ] 原有标签得到保留
- [ ] `final_note` 通过格式验收
- [ ] 没有为了模板而过度结构化
- [ ] 内容不超过 2000 字
- [ ] 没有输出 webhook 或 `.env` 内容

---

## 调用方式

优先通过 stdin 传递内容：

```bash
python3 flomo_sync.py <<'FLOMO_NOTE'
**笔记标题**

笔记正文。

#标签
FLOMO_NOTE
```

不要优先使用位置参数传递复杂 Markdown，因为内容中可能包含：

- 引号
- 换行
- 反引号
- 表格
- shell 特殊字符

需要预览时：

```bash
python3 flomo_sync.py --dry-run <<'FLOMO_NOTE'
笔记内容
FLOMO_NOTE
```

需要 JSON 结果时：

```bash
python3 flomo_sync.py --json <<'FLOMO_NOTE'
笔记内容
FLOMO_NOTE
```

---

## 返回规则

同步成功后，只需返回：

```text
已同步到 Flomo。
```

如果用户需要查看整理结果，可以返回：

```text
已按原结构整理并同步到 Flomo。
```

同步失败时，返回简洁且可操作的错误原因，例如：

- 未找到 `.env`
- 未配置 `flomo_api`
- 内容超过 2000 字
- Flomo API 返回错误
- 网络连接失败

不要返回：

- webhook URL
- `.env` 内容
- 完整请求体
- 无关的程序调试信息

## 示例

### 用户输入

```text
不同资产的完整映射\n\n大类资产 | 风险暴露 | 交易工具 | 底层资产\n股票 | A股乘用车 | 个股、汽车ETF | 上市公司股权\n股票 | 沪深300 | 沪深300ETF、股指期货 | 300只成分股或指数合约\n债券 | 中国国债 | 国债、国债ETF、国债期货 | 国债或国债期货合约\n商品 | 黄金 | 金条、黄金ETF、黄金期货 | 黄金现货或期货合约\n商品 | 原油 | 原油ETF、原油期货 | 原油期货合约或现货\n房地产 | 商业基础设施 | 公募REITs | 产业园、仓储、公路等项目及现金流\n现金类 | 短期无风险收益 | 货币基金、存款 | 存款、同业存单、短期债券\n外汇 | 美元 | 美元存款、外汇ETF、期货 | 美元现金、存款或外汇合约\n\n最简洁的定义：\n大类资产：决定收益来自哪一种经济资产。\n风险暴露：决定具体承担哪一种价格或因子变化。\n交易工具：投资者实际下单买卖的对象。\n底层资产：交易工具背后真正持有、跟踪或引用的资产。\n\n一句话总结：大类资产决定投什么世界，风险暴露决定押注什么方向，交易工具决定怎么买，底层资产决定最终拥有什么。\n\n#资产映射 #交易
```

### 应整理为

```markdown
**不同资产的完整映射**

映射顺序：**大类资产 → 风险暴露 → 交易工具 → 底层资产**

- **股票** → A股乘用车 → 个股、汽车 ETF → 上市公司股权
- **股票** → 沪深300 → 沪深300 ETF、股指期货 → 300只成分股或指数合约
- **债券** → 中国国债 → 国债、国债 ETF、国债期货 → 国债或国债期货合约
- **商品** → 黄金 → 金条、黄金 ETF、黄金期货 → 黄金现货或期货合约
- **商品** → 原油 → 原油 ETF、原油期货 → 原油期货合约或现货
- **房地产** → 商业基础设施 → 公募 REITs → 产业园、仓储、公路等项目及现金流
- **现金类** → 短期无风险收益 → 货币基金、存款 → 存款、同业存单、短期债券
- **外汇** → 美元 → 美元存款、外汇 ETF、期货 → 美元现金、存款或外汇合约

**最简洁的定义**

- **大类资产**：决定收益来自哪一种经济资产。
- **风险暴露**：决定具体承担哪一种价格或因子变化。
- **交易工具**：投资者实际下单买卖的对象。
- **底层资产**：交易工具背后真正持有、跟踪或引用的资产。

**一句话总结**

大类资产决定投什么世界，风险暴露决定押注什么方向，交易工具决定怎么买，底层资产决定最终拥有什么。

#资产映射 #交易
```

## 约束

- 不修改用户本地笔记原文
- 不访问与当前同步无关的文件
- 不输出 webhook
- 不输出 `.env`
- 不在用户未表达同步意图时自动发送
- 不以“优化”为理由增加未经用户表达的内容
- 不用固定模板覆盖用户已经清楚的结构
- 禁止将包含竖线分隔结构的原始内容直接传给脚本（除非用户明确要求原样同步）
- `final_note` 必须通过格式验收才能调用脚本
