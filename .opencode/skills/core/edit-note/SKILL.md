## 你要做什么

- 按推荐的文章骨架，重新组织用户现有内容的标题层级、段落顺序与区块结构
- 只做编辑整理，不重写作者的核心表达、判断句与论证路径
- 优化格式表现：列表化、表格化、分段、标题整理、标点与空行统一
- 修正明显错字、病句或重复，但以最小改动为原则
- 对暂时没有内容但结构上应该存在的部分，先保留空位，并明确标记“待补充”

## 推荐骨架

- 标题
- 一句话结论 / 主题定义
- 背景 / 要解决的问题
- 核心判断
- 展开分析
- 例子 / 清单 / 对照表
- 下一步 / 待补充

如果原文已经隐含了更合适的结构，可以在不改变原意的前提下微调骨架顺序。

## 输出格式

- 1 篇整理后的 Markdown 笔记
- 保留清晰的标题层级
- 适合列表的内容改成列表
- 适合对比的信息改成表格
- 缺失内容的位置保留标题或区块，并标注“待补充”

## 约束

- 保留 Obsidian 链接格式（如 [[Note]]、![[image.png]]）
- 不重写核心论证，不补写作者没有表达过的新观点
- 不把原文整体改写成另一种文风，尽量保留口语感和判断句
- 只做结构调整、格式优化、错字修正、表格化和重复删减
- 若信息不足，宁可留空并标注“待补充”，不要自行编造内容
